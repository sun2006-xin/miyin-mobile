# 发行签名与自动化

## 当前状态

preview68及以前使用旧测试签名。preview69开始接入独立正式发行密钥，
公开证书与指纹位于本目录的`signing/`。私钥和密码不在仓库内。

长期发行签名的流程：用Android Studio或keytool生成独立发行密钥库；
将私钥和密码保存在仓库外，至少两处安全备份；记录公开证书指纹；
配置Gradle从本机私有配置或环境读取签名；验证新包的签名、安装和后续覆盖升级。
私钥、密码不能提交到公开Git。云端签名应通过GitHub Actions Secrets提供，
并只在可信发行流程中使用，不提供给外部PR。

迁移包使用apksigner签名轮换证明：Android9/API28及以上使用新的正式密钥；
Android7/8/API24～27保留旧签名兼容路径。签名工具已分别验证这三个API范围，
OPPO/Android12已接受旧preview68到新签名的原地覆盖升级，未卸载，应用UID与
首次安装时间一致。其他系统的真机升级仍需扩展验收，不能以静态验证代替。
新的签名链不允许用旧签名回滚覆盖已迁移安装。

密钥在本机仓库外保存并有另一磁盘副本，访问限制为当前用户与SYSTEM。
两份副本都在同一电脑，仍应由维护者安排离机备份。不要把凭据、密钥库或
密码放进Issue、PR、日志或公开附件。

参考：https://developer.android.com/studio/publish/app-signing

## 自动检查

`Source checks`在相关源码提交、Pull Request或手动触发时运行：Flutter依赖、
Dart测试、网页逻辑、浏览器交互及发音词典转换器测试。
该流程不下载LFS大模型，不做手机原生推理或音频听感验收。

`Build signed Android release`在Actions页面手动运行，仅允许main分支使用
`miyin-release`受保护环境中的密钥。先取回LFS模型、生成未签名APK，再执行
固定密钥签名、公开证书指纹核对和分卷校验准备，保存7天的Actions构建产物。
缺少密钥、签名失败或指纹不匹配时直接失败，不回退成临时测试签名。
临时密钥文件在任务结束时清理，构建产物仅包含分卷、说明、校验与公开签名信息。
流程不会自动替换公开Release，公开下载版需核对产物并完成发行记录。

完整模型和APK较大，手动构建会消耗LFS下载量、运行时间和产物空间，
所以不在每次修改README时构建完整包。Actions产物与公开Release下载区不同。
是否成功以实际运行结果为准，配置文件存在不等于云端构建已经通过。
