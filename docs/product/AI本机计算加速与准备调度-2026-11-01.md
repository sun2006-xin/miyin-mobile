# AI 本机计算加速与准备调度

本轮是开发候选验证，不代表正式发布或全部语音体验验收。语音缓存改造见《AI语音有界准备与缓存验收-2026-11-01》。

## 改动范围

固定 llama.cpp revision `d854d98bae598388ecea1ed84396587e5edc326d` 和内置 Qwen3.5-2B Q4_K_M 模型不变，接入上游 ARM CPU 动态分派。APK 同时携带 ARMv8.0 兼容模块及 dotprod/FP16 模块，由上游特征检测选择；没有强制所有设备执行高级指令。

模型运行仍使用 4096 上下文、4 线程、单并发、带临时认证的本机回环接口。仅增加共享依赖的固定 nativeLibraryDir 查找路径；不改系统提示、模型知识、回答、音色、语速或界面布局。构建关闭预构建与本地 WebUI，最终嵌入 0 个网页资产，不在手机运行时下载计算引擎。

构建方法见《本机聊天计算引擎构建-2026-11-01》，最终九个 ELF 的依赖、大小与 SHA256 保存在应用 `assets/chat-model/runtime-manifest.json`。

## 独立设备对照

OPPO PEHM00 / Android 12。同一已校验模型，固定 4 线程、batch/ubatch 128、GPU layers 0；官方 llama-bench 以 ABBA 顺序运行。A/B 公共二进制逐字节相同，B 仅增加 dotprod CPU 模块。

| 次序 | 模块 | 提示处理 tok/s | 生成 tok/s |
| --- | --- | ---: | ---: |
| A1 | ARMv8.0 | 5.744 | 5.321 |
| B1 | dotprod/FP16 | 10.907 | 7.069 |
| B2 | dotprod/FP16 | 29.674 | 7.082 |
| A2 | ARMv8.0 | 5.225 | 5.327 |

生成速度均值从 5.324 到 7.076 tok/s，增加 32.9%。B 提示处理波动显著，不能称固定 3.7 倍提速。记录的 CPU 最大温度从初始约 32.9°C 到最终 44.5°C；电池 28.3°C 到 29.5°C。

独立 HTTP 服务采用应用默认参数（batch 2048、ubatch 512，构建只有 CPU 后端）；同一合成中文提示 38 prompt tokens、20 completion tokens。请求关闭思考且 `cache_prompt:false`，两轮均无提示缓存命中。

## 冷加载与完整应用的限制

- 独立服务 health ready：基线 2172 ms，dotprod 首测 21531 ms，完全相同参数复测 6562 ms。异常慢轮主要发生在 threadpool init 之后，原因未确定。
- 上游 warmup 使用最多两个 BOS/EOS token；没有证据支持“batch 2048 导致预热 2048 token”，也没有据此修改应用参数。
- +48 完整应用中，模型加载与旧回答语音准备重叠，prepare 为 26887 ms；一次热模型请求 `reused=true / launches=1 / native prepare=1 ms`，已有五条上下文消息时首内容仍为 14856 ms，界面完整显示回复。此样本不能与独立服务的 38 token 提示横比，不能宣称应用首字已经降至 1.6 秒。
- +49 将已完成回复的推测性语音准备排在 `warmLocal()` 完成之后，避免模型加载期间启动该批声学合成。真实朗读请求不等待这批推测任务。离开页面、开始播放等代次检查在等待后仍生效。
- +49 已安装 OPPO 并实际进入同一聊天，冷准备 25365 ms；语音准备发生在模型 ready 之后。本次最新回复已是两字，不能与此前 82 字准备的耗时作公平百分比比较。排队正确不表示冷加载已经变快；本次仍约 25 秒。
- APK 安装与服务启动证明 native 依赖可加载；独立设备程序已验证两种 CPU 模块及高级模块实际映射。Android 对发布应用进程的 `/proc/PID/maps` 拒绝 shell 读取，未把独立进程的映射当作已读取发布应用映射。
