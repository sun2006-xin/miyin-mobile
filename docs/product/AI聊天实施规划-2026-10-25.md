# 觅音 AI 聊天实施规划（讨论稿）

日期：2026-10-25。状态：用户已选择 DeepSeek，随后明确暂不填写 API Key，先完成模型选择、服务配置和隐私设置。真实服务验收暂缓，不作为当前基础设置交付的前置条件。现有布局、外观搭配与语音球体作为界面基线。

## 当前事实

- 文字聊天已有消息流、输入框、模型选择、附件入口、停止/重新生成、朗读/复制/分享与分类历史界面。
- Android 首轮新增 DeepSeek 真实流式通路、手机端模型配置和 SQLite 会话快照；浏览器预览仍保留演示通路。真实服务调用尚未用用户密钥验收。
- AI 语音球体已有沉浸与字幕两态，真实会话服务尚未接入。
- 翻译、同传、OCR、本地语音识别和合成已有可复用原生服务；这些服务不等于 AI 对话模型。

## 建议的产品范围

### 第一阶段：可持续使用的文字聊天

1. 在已有设置入口添加服务地址、API Key、模型名称、连接检查、模型列表与默认模型选择。沿用用户自行配置并主动选择服务的既定路线。
2. 支持流式回答、停止、重试、复制、系统分享和重新生成；失败时保留输入与已生成内容，明确显示错误。
3. 会话和消息写入 SQLite，保存模型、消息时间、生成状态与上下文来源；重启可继续，退出不会丢失已完成内容。
4. 历史会话改名、搜索、继续、删除和分享；清除正在生成的会话先取消对应请求。
5. 第一批采用可配置的 OpenAI 兼容协议适配器。厂商专属协议通过独立适配器增加，不在界面层判断厂商。

### 第二阶段：资料与会议上下文

1. 复用已有“从历史添加”，仅提交用户明确选择的翻译、文章、面对面或同传文字片段。
2. 将会议内容按时间和音源组织，支持纪要、待办提取、段落定位；模型回答应标注来自哪个会话/片段。
3. 图片按所选模型能力决定直接图像输入或先用本机 OCR；发送前明确展示附件及采用方式，不静默上传音频或整场录屏。
4. 文本文件先做有界导入和分段。Word/PDF 作为后续同模块扩展，先明确支持格式和大小，不把复杂文档解析混入首个可交付增量。
5. 设定上下文预算和截断提示；长会话按预算纳入近期消息与显式附件，禁止悄悄丢弃用户选择的重要资料。

### 第三阶段：同一会话的语音对话

1. 复用本机 ASR → 对话模型 → 本机 TTS，文字与球体两态共享同一会话及消息顺序。
2. 以可完成的句子逐步合成朗读，避免等待整篇回答。关闭语音/退出/中断时同时取消生成及待播队列。
3. 麦克风静音、暂停朗读、手动打断均有明确状态；先完成按键中断，验证回声抑制后再开放自动语音打断。
4. 摄像头、屏幕共享等入口按模型能力逐项接入；未实现的能力明确标注，不用模拟回复冒充完成。

## 模块与数据架构

| 模块 | 责任 |
| --- | --- |
| 现有本地页面 | 消息展示、草稿、附件预览、用户操作，不持有 API Key |
| ChatRpcRouter | 校验消息/附件大小、会话 ID、请求 ID、取消与事件协议 |
| ChatSessionController | 编排会话、生成状态、上下文预算与失败恢复 |
| ChatRepository | SQLite 会话/消息/附件快照/生成状态；旧网页历史幂等迁移 |
| ProviderRegistry / ChatProvider | 根据用户选择配置协议适配器；连接检查、流式事件、超时与取消 |
| SecretStore | Android Keystore 保护的凭据；密钥不进入网页存储、日志、分享或版本库 |
| ContextAssembler | 将用户选择的记录转换为有时间和来源标记的文本；保留可追溯引用 |
| VoiceConversationController | 复用本机 ASR/TTS；管理录音、思考、朗读、静音与中断 |

建议新增路径：`lib/features/chat/`（配置、适配器、编排、语音控制），`lib/core/storage/chat_repository.dart`（持久化），`assets/miyin_v5/miyin-chat.js`（现有聊天界面的真实事件适配）。避免继续把网络请求和会话逻辑塞入 `index.html`。

生成状态：queued → streaming → completed / failed / canceled。每次请求携带独立 ID；过期的增量和回调不能修改已切换或已取消的消息。单个会话同一时刻只允许一个生成任务，跨会话并发先限制数量。

网页只接收 `started / delta / completed / failed / canceled` 等可见事件。网络连接、凭据和取消放在原生层；连接检查不发送历史资料。无有效配置时显示设置入口，不静默切换到其他服务。

## 执行顺序与验收

| 增量 | 交付 | 验收 |
| --- | --- | --- |
| A | 数据模型、事件/取消协议、SQLite 仓库与旧记录迁移 | 空会话、重启继续、幂等迁移、删除与中断、超长内容边界 |
| B | 凭据存储、服务配置、连接检查和模型选择 | 无效地址/密钥/模型、超时、日志脱敏、清除配置 |
| C | 首个真实流式文字对话与现有界面整合 | 首字显示、停止、断网、重试、切换会话、后台/前台恢复 |
| D | 附件和会议文字上下文、引用定位 | 用户选择可见、大小预算、来源删除、无关历史不进入请求 |
| E | 同会话语音输入和分句朗读 | 连续往返、静音、中断、回声、异常退出不残留录音/播放 |
| F | 用户现场验收与版本发布 | 真机体验、耗时/内存、失败恢复、分享与历史完整性 |

每个增量独立核对与交付，再进入下一增量。真模型调用验收使用用户明确提供并选择的配置，不从电脑上其他工具的凭据里借用模型密钥。

## 待讨论的取舍

- 默认沿用“用户配置自己的模型服务”；若需要普通用户安装即聊，应单独设计服务端、登录、额度和费用承担。
- 建议先把文字聊天与本地历史做完整，再接附件和语音对话，避免同时更改全部数据链路。
- 当前不承诺内置手机端大语言模型、跨设备同步、自动联网搜索或通用 Agent 工具执行；这些需要独立讨论资源、权限和费用。

## 本轮执行记录

- 首个服务商确认：DeepSeek，使用其官方 HTTPS 地址，账户可用模型从 `/models` 获取。
- 首轮采取普通文字模式，关闭思考模式；后续思考档位另行接入。
- 密钥通过 Flutter 原生对话框填写，由 Android Keystore AES-GCM 加密保存，网页不接收密钥。
- 停止生成关闭该请求的独立网络连接；过期事件按请求编号隔离；已收到的文字在停止或失败后保留。
- 会话以兼容现有界面的 JSON 快照逐会话写入 SQLite，旧网页会话按迁移标记导入一次。当前并非已完成规范化的消息/附件数据库模型。
- Android 的附件、会议上下文、语音对话与回答朗读先提示尚未接入，不使用原有演示回复冒充真实服务。这些仍属于后续增量。
- 候选包版本标识：1.6.0-preview+15；本轮不覆盖已发布的 V1.5.1 稳定版。
- 新增聊天模块静态分析无问题，已完成首个候选 APK 构建；真实模型连接、首字延迟、停止、断网恢复和重启继续，仍需要配置密钥后验收。
- 用户追加决定：先不使用 API。模型选择、服务配置、AI 隐私分别独立入口；没有密钥也能保存默认模型和自定义模型 ID。
- AI 隐私包含远程发送许可、当前会话上下文、本机历史保存；远程发送默认关闭，实际请求在原生层再次检查。已有“保存会话历史”开关与新入口同步。
