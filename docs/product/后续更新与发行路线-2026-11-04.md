# 应用内自动更新与发行路线

## 已发布与待开发的边界

当前目标版为 `1.6.0-preview+70`。在应用内加入 Android 后台版本检查、非计量网络分卷下载、SHA-256 校验和 PackageInstaller 安装交接。GitHub Actions 在 `pubspec.yaml` 版本号变更进入 `main` 后自动构建并签名；成功后发布 GitHub Pre-release，并将经验证的版本与下载地址写入 `docs/release/update.json`，供已安装版本读取。

## 已实现的更新路径

用户无需手动检查更新或打开网页。实现路径如下：

- 应用启动时和每12小时由 WorkManager 安排一次版本清单检查；系统可因省电和网络状态延迟执行。
- 清单固定读取 GitHub `main` 上的 `docs/release/update.json`，不使用会忽略预发布版的 latest Release 端点。
- 下载由 Android DownloadManager 执行，设置为不通过计量网络或漫游下载；系统负责在网络中断后继续或重试。
- 安装前逐卷检查长度与 SHA-256，再流式写入一个 PackageInstaller 会话并核对整包 SHA-256；Android 安装器再检查 APK 签名。
- 如果当前设备未允许觅音安装应用，应用会在包准备好后提示前往 Android 系统授权。普通应用无法保证静默安装；部分设备还会要求确认系统安装提示。
- 自动更新需要访问 GitHub；在所在网络无法访问 GitHub 时，检查和下载会等待网络恢复。完整包约2.23GB，没有差分更新。
- PackageInstaller 在系统允许时请求免操作更新；实际是否显示确认由安装器、签名安装来源、Android版本和厂商策略决定，不能视为已在所有手机验证通过。

增量更新包、备份和跨手机同步不在本轮范围。应用仍需下载完整安装包。

## 历史开发资料与公开下载

当前构建源码以main为准，用户下载从公开Release进入。旧实验APK和历史
开发参考资料仅以维护者可见的草稿附件保存，不作为公开推荐版本；它们的
旧组件、旧签名和验收结论不能沿用当前版本说明。清理本机唯一副本前，逐个
核对远端附件的文件大小与SHA256；可再生成的缓存与原始设备诊断不公开上传。
